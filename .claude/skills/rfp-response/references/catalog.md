## Choosing between close matches

- An RFP naming a specific system a buyer's *customers* use (patients, constituents, members, students) usually wants an **Industry Solutions** offering, not a generic custom app.
- "Reporting is slow / numbers disagree" → `data-warehouse` if they need one governed source of truth; `bi-dashboards` if the warehouse exists and they need the front end; `data-integration` if the ask is moving data, not analysing it.
- "Connect our systems" → `systems-integration` for internal workflows; `api-platform` when they want reusable, governed APIs for internal or partner developers.
- "Replace our old system" → `legacy-modernization` when the existing system must keep running during transition; `web-app-platform` for a clean-sheet build.
- An RFP that is mostly about running software someone already built → `managed-services`; one that is mostly assessment and hardening → `security-compliance`.
- A large RFP can legitimately span two offerings. Lead with the primary one and name the second as an added workstream, priced separately.
