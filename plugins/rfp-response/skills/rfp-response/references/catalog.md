## Telling close matches apart

These are where offering selection goes wrong, so check here before committing to a match.

- An RFP naming a system the buyer's own *customers* use — patients, constituents, members, students — usually wants an **Industry Solutions** offering, not a generic custom app.
- "Reporting is slow / our numbers disagree" → `data-warehouse` when they need one governed source of truth; `bi-dashboards` when the warehouse exists and the gap is the front end; `data-integration` when the ask is moving data rather than analysing it.
- "Connect our systems" → `systems-integration` for internal workflows; `api-platform` when they want reusable, governed APIs for internal or partner developers.
- "Replace our old system" → `legacy-modernization` when the existing system must keep running during transition; `web-app-platform` for a clean-sheet build.
- Mostly about running software someone already built → `managed-services`; mostly assessment and hardening → `security-compliance`.
- A large RFP can legitimately span two offerings. Lead with the primary one and name the second as a separately priced workstream.
